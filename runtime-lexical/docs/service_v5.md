# 文本服务 v5：退步题的分块诊断与修复

仍只使用原100题、原文和已有缓存。模型 API 与新 subagent 均为0，没有产生新答案或 Judge 评分。原始 LoCoMo 22/50（44分）、冻结 v7 及 v2/v3/v4 归档保留。

## 为什么 v4 的一题下降

固定集合中的问题是“Did John and James study together?”。原始金标引用 D17:13 与 D17:16：原文分别提到 elementary school、left class early。查询词干为 studi/togeth，完整证据所在原文块没有这两个词，所以不进入新增的整块内容词法通道；只从细粒度通道获得半权重 RRF 分。

原文 D17:13 恰好被256词边界切成两块。v4 把前块从第40名提升到第7名，其中包含 Studying opening moves，但只覆盖金标发言开头；后块包含学校与课堂的完整上下文，从v3第38名降到v4第42名。这题的48,000字符完整记录前缀只能容纳39条，因此实际金标轮次 token 覆盖从100%降到13.33%。不是金标被修改、缓存缺失或完整前100条漏召回。

详细索引、词法名次、原文、跨块轮次偏移和来源记录在 `runs/text_turn_regression_diagnosis_001/diagnosis.json`。金标只由外部诊断器读取，不传入服务。

## 修复规则与未采用的方案

先比较“所有跨块发言邻居都获得锚点一半分数”的单步补全。原题恢复到100%，但LoCoMo来源@48k从96%降到91%，实际轮次 token 覆盖94.37%降到90.84%，5题退步；该方案未接入默认路径。

采用的规则只处理单块缺口：中间块与前后块各有已识别的同轮发言跨块关系，而且前后块都在原始排名中。中间块可获得较弱一侧锚点分数的一半，与自身原分取较大者。分数只读取原始排名，提升后的块不会继续传播；相同日期、同一说话人或一般会话邻接均不足以直接建立边。

规则沿用所有明确具名对话的结构，不使用题号、人名常量、标准答案、金标、主题词或专用同义词。默认服务只调用 `bridge_turns`；单边补全保留用于离线消融。输出依旧是相同完整原文块，ID、原文、时间、向量、top_k 与字符预算均不变。
