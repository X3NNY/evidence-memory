# 文本服务 v4：恢复对话结构与双粒度检索

本轮只用原100道题和已有缓存，模型 API 与新 subagent 均为0；原始 LoCoMo 问答22/50（44分）保持不变。v2/v3 的报告与部署包、冻结离线 v7 均保留。

## 问题与改动

HTTP 输入的已缓存原文块包含明确的交替说话人，但旧线上索引把整块都标成外层 user，使具名问题的内容词排序无法激活。原 LoCoMo 的50题在前100条已经都能找到金标来源，瓶颈主要是相关证据的排名与有限上下文内的取舍。

新内部视图仅依据原文识别2–8位反复出现的具名说话人：每位至少3次，并要求同一块内至少4个标签且交替至少3次；通用元数据标题和角色标签排除。拆出实际轮次后复用冻结 v7 的内容词排序。仅对提及明确参与者的查询，再将细粒度证据名次与完整原文块内容 BM25 名次按等权 RRF、k=20融合。内容通道去除参与者名字与功能词，并使用现有 Porter 词干算法；保留否定和时间词，不加入题目答案或主题同义词。

没有说话人增权或硬过滤。两个视图仍映射到相同完整原文块；ID、正文、时间、缓存向量、最大 top_k=100 和 HTTP 返回粒度不变。只改变具名对话的检索排序及分数。未识别为该结构的普通角色消息沿用原策略。

LongMemEval-S 的50题排序、分数、原文、ID与时间保持一致；其中47题为证据召回正例，3题为 abstention。R10仍为76.21%，48k来源召回93.01%，48k实际答案轮次 token 覆盖77.32%。来源召回不等于完整答案轮次覆盖，两者都不是问答分数或平台正式分数。

同一48k前缀按真实输出顺序选取完整记录，日期、角色、Document标题和分隔符均计入预算，第一条放不下的记录之后不再跳选。独立评测器从原始数据重建并逐字核对缓存块、金标轮次与可见词位置；部分轮次不会因命中同一来源而获得完整覆盖。评测金标始终在服务接口外。

## 消融与验证产物

本轮固定比较恢复结构、说话人1.25倍、完整块内容0.25权重、二者组合，以及完整块内容等权融合。恢复结构和说话人组合存在R10退步，未设为默认；单纯内容0.25带来的增益较小，采用最终等权方案。不增加返回量或上下文预算。

- `runs/text_dialogue_parent_balanced_001/`：采用方案的计划、100题新旧 HTTP 输出、来源评分、独立轮次评分、源码快照。
- `runs/text_dialogue_default_002/`：未打补丁的默认服务逐条核对100题采用方案；普通 LongMemEval 响应与冻结 v3 完全一致。
- `runs/text_hybrid_release_003/`：测试、源码部署包和最终报告。

仅在完整研究工作区、原数据与缓存齐全时可运行以下零模型调用复核；输出必须用新目录：

```powershell
$env:AML_ALLOW_EMBEDDING_API = '0'
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = '1'
python -m pytest -q
python scripts/verify_dialogue_release.py --output runs/text_dialogue_default_repeat
python scripts/smoke_hybrid_service.py --output runs/text_hybrid_local_repeat
```

默认服务检索复核使用数据库副本；向量 provider 替换为缺失即报错的实现，并阻断外网。原始 embedding 缓存只读、哈希不变，原始44分对应的537份结果和报告按清单逐个校验。内核与离线文本适配器源码不变，冻结 v7 仍与已通过的逐字节回归一致。

这100题包含已经反复使用的原回归题，本轮依据整个固定集合比较候选，不是新的留出或盲测；存在个别题退步，最终报告保留逐题变化。输入是历史缓存的256词块及原会话分组，尚未验证官方原始消息写入格式的收益。无新问答、无公网部署、无官方 Smoke/Full。
